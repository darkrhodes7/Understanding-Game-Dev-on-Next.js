# AI RPG Chatbot Menu System — Design Plan

## Context

- **Platform**: CHUB.ai (supports full markdown rendering)
- **Format**: Lorebook entries + System Prompt instructions
- **Character**: Kuro Rhodes — Void God (Sovereign), Level 100, Isekai setting
- **Goal**: Replace all ASCII box-drawing menus with responsive, resize-safe markdown menus
- **Commands**: `/status` (or `/stats`), `/inv`, `/quests`, `/party`, `/family`, `/harem`, `/kingdom`

---

## The Core Problem: Why the Current Menu Breaks

The existing menu uses **Unicode box-drawing characters**:
```
╔════════════════════════╗
║ text padded with spaces║
╚════════════════════════╝
```
These characters have **fixed visual widths**. When the chat window resizes:
- The right edges no longer line up
- Lines wrap mid-box creating broken `║` fragments floating alone
- The inner padding (spaces) becomes misaligned

**They cannot be fixed** — they are fundamentally incompatible with fluid-width containers.

**The solution: Pure Markdown** — headers, tables, bullet lists, and horizontal rules. These reflow perfectly at any width because they are rendered by the browser's layout engine, not painted with characters.

---

## What Is Being Preserved From the Original Menu

The original `/status` menu had these unique sections — **all are kept**, just reformatted:

| Original Section | Content | New Format |
|---|---|---|
| Header identity block | Entity, Class, Level, Void, Economy (GP/Tether Tokens) | Bold inline stats + `---` divider |
| The Abyssal Engine | HP/MP/SP with regen rates and progress bars | Markdown table |
| Core Attributes | STR END CON AGI DEX / INT WIS SPR CHR MAG (10 stats) | Markdown table |
| Biological Armament | Weapon spec, scaling, payload, status | Bullet list with bold labels |
| Carnal Dominions | Bound Entities (The Pack), Alpha-Aura, Feral Miasma | Bullet list with state labels |

> **Note on progress bars**: `[██████████]` block-fill bars use full-block Unicode (`█`) which renders fine since it doesn't need to align to a fixed-width column — it's just text content inside a table cell. These are kept.

---

## Design Philosophy: Markdown-Only

These markdown elements are safe and reflow correctly on CHUB.ai:

| Element | Syntax | Use For |
|---|---|---|
| Level 2 header | `## Title` | Menu title |
| Level 3 header | `### Section` | Subsection headers |
| Horizontal rule | `---` | Visual separators (replaces `╠════╣`) |
| Bold text | `**label**` | Stat names, labels |
| Italic text | `*flavor text*` | Descriptions, lore, state labels |
| Markdown table | `\| Col \| Col \|` | Stats, resources, comparisons |
| Bullet list | `- item` | Inventory, members, armament details |
| Blockquote | `> text` | System notes, flavor lore |
| Emoji | 🐺 💪 ⚖️ etc. | Kept — emojis render fine in markdown |

**What to NEVER use again:**
- `╔ ╗ ╚ ╝ ║ ═` box-drawing characters
- `┌ ┐ └ ┘ │ ─` light box characters
- Any fixed-width space-padded ASCII layout
- `├─` tree connectors inside bordered boxes (fine as bullet list items, bad in boxes)

---

## Implementation: CHUB.ai Lorebook Entries

Each slash command gets its own **Lorebook Entry**:
- **Keyword**: The slash command (e.g., `/status`, `/inv`)
- **Secondary keywords**: Aliases (e.g., `status menu`, `check stats` — as in the original)
- **Content**: AI formatting instructions + the exact markdown template
- **Insertion Order**: 2 (high priority, injected early)
- **Always Active**: No (keyword-triggered)
- **Recursive Scanning**: OFF

A **System Prompt block** sets global slash command behavior.

---

## 1. System Prompt Block (Global Rules)

Add this to the world/character system prompt:

```
## Slash Command System

When {{user}} types any slash command listed below, immediately pause the narrative and output the corresponding menu in clean markdown format. Do not truncate any section. Fill all [bracketed variables] with current story-accurate values. After the menu, resume the narrative naturally on a new line.

Commands: /status (aliases: "status menu", "check stats") | /inv | /quests | /party | /family | /harem | /kingdom | /menu

FORMATTING RULES — follow precisely:
- Use ## for the menu title, ### for section headers
- Use --- as section dividers (never ╠═══╣ or similar)
- Use markdown tables for numerical or comparative data
- Use bullet lists (- item) for collections, equipment, members
- Keep emoji labels where they add clarity (they render fine)
- NEVER use box-drawing characters: ╔ ╗ ╚ ╝ ║ ═ ╠ ╣
- NEVER use space-padded fixed-width columns
- Progress bars using █ characters inside table cells are acceptable
```

## Notes

- **Emojis are kept** — they render fine in CHUB.ai markdown and preserve the visual identity of the original.
- **Progress bars (`█`) are kept** — they live inside table cells, not inside fixed-width ASCII boxes, so they don't cause alignment issues.
- **The Biological Armament and Carnal Dominions sections are fully preserved** — only the outer box is removed; the content is identical.
- **Tables reflow automatically** — CHUB.ai renders GFM (GitHub Flavored Markdown) tables natively. They will adapt to any chat window width.
- **The `---` divider** replaces `╠════╣` section separators and renders as a clean horizontal line.
- **Keyword aliases** (`status menu`, `check stats`) are preserved exactly as they were in the original system instruction, so existing habits still work.
- The 10 core attributes are split into two tables (5+5) to avoid wide tables becoming cramped on narrow screens.
